# Mugshot

基于 TRSS-Yunzai 的设备状态远程查看系统。群成员在 QQ 群内发送指令，即可查看群主 Android 设备的当前使用状态：正在使用什么 App、屏幕是否亮着、电量、电池温度、充电状态、网络类型、设备名称等，还能看到同时可见的分屏/小窗应用、后台运行中的应用，以及最近 24 小时各应用的使用时长。支持多台 Android 设备同时接入，每台设备可在 App 内自定义名称，群内指令按设备名查询；App 还可选连接 HryFine 蓝牙手表，把步数、心率、血压、血氧与睡眠一并纳入状态卡片。

## 三个组件

| 组件 | 目录 | 说明 |
| --- | --- | --- |
| Mugshot（Android 上报端） | `android/` | Kotlin 应用，采集前台应用、分屏/小窗可见应用、后台应用、屏幕状态、电量与电池温度、充电、网络类型与最近 24 小时应用使用时长，通过 WebSocket 定时上报，并响应服务端按需上报指令；可选连接 HryFine 蓝牙手表，一并上报步数、心率、血压、血氧与睡眠；内置"运行日志"页，默认只看本次运行，可切换最近 24 小时历史 |
| mugshot-server（Linux 服务端） | `server/` | Go 编写，Ubuntu ARM64 与 x86_64 均有预编译包，接收多设备上报、维护设备在线状态表、提供 HTTP 查询 API 与 WebSocket 长连接、支持向设备下发 `request_report` 按需上报指令 |
| Mugshot（TRSS-Yunzai 插件） | `plugins/mugshot/` | ESM 插件，连接服务端，接收 QQ 群指令，渲染状态卡片图片并通过 QQBot 按钮交互 |

## 架构

```
┌─────────────────┐   WebSocket(定时上报/heartbeat)      ┌──────────────────┐
│ Mugshot Android │ ──────────────────────────────────▶ │                  │
│  设备A/设备B/...  │ ◀──────── request_report ────────── │  mugshot-server  │
└─────────────────┘                                      │  (systemd 常驻)   │
                                                         │                  │
┌─────────────────┐   HTTP 查询(/status /devices)        │                  │
│ Mugshot 插件     │ ──────────────────────────────────▶ │                  │
│ (TRSS-Yunzai)   │ ◀──────── live/cache 数据 ────────── │                  │
└─────────────────┘                                      └──────────────────┘
        │
        ▼  e.runtime.render 渲染图片 + QQBot 按钮
   QQ 群消息
```

## 群内指令

下表以默认前缀 `群主` 为例；修改别名后前缀随之变化，规则见下文「指令别名」。

| 指令 | 说明 | 权限 |
| --- | --- | --- |
| `#群主帮助` | 查看指令列表 | 所有人 |
| `#群主列表` | 渲染所有设备列表（在线状态、最后上报时间），附选择按钮 | 所有人 |
| `#群主查看 [设备名]` | 查询设备当前状态，默认触发一次按需上报（fresh），返回 live 数据；设备离线或超时降级返回 cache 数据 | 所有人 |
| `#群主在干嘛 [设备名]` | 同 `#群主查看`，卡片附带每台设备近 24 小时使用最多的 3 个应用（时长 + 打开次数） | 所有人 |
| `#群主详情 [设备名]` | 返回完整字段状态卡片 | 所有人 |
| `#群主用过什么` | 渲染各设备最近 24 小时的软件使用时长与打开次数（按前台时长排序，含占比条） | 所有人 |
| `#群主更新` | 检查并更新插件自身（宿主更新机制支持时自动装依赖并重启，失败回退 git 直拉）；服务端更新走其自身检查或 GUI | Master |
| `#群主更新日志` | 查看插件最近提交记录 | 所有人 |

`#群主查看` / `#群主在干嘛` 不带设备名时渲染全部设备状态卡片，可再加设备名查看单台。

### 指令别名

默认前缀是 `群主`，可改成任意好记的词（例如 `huli`），让群内指令变成 `#huli查看`、`#huli列表`。

**修改方式**

- 锅巴面板：插件配置 →「指令」→「指令别名」，保存后下一条消息即生效，无需重启 Yunzai
- 配置文件：编辑 `<Yunzai根目录>/config/mugshot.yaml` 的 `alias` 字段，重启 Yunzai 后生效

```yaml
alias: "群主"
```

**生效范围**

| 项目 | 行为 |
| --- | --- |
| 查询类指令 | 跟随别名：`查看`、`详情`、`在干嘛`、`列表`、`用过什么`、`状态`、`更新日志` |
| 帮助指令 | 固定为 `#群主帮助`，不随别名变化，避免改名后找不到入口 |
| 更新指令 | 固定为 `#群主更新`，改错别名时仍能更新插件恢复 |
| 卡片与按钮 | 提示文案、QQBot 按钮里的指令同步换成新前缀 |
| 旧前缀 | 改名后立即失效，不再响应 |
| 其他插件 | 前缀不匹配时插件直接放行，不会误吞别家指令 |

**校验规则**

- 允许中文、英文字母、数字、下划线，长度 1-12 位
- 开头的 `#` 会自动去掉，例如填 `#huli` 等同 `huli`
- 留空或包含其他字符时回退默认值 `群主`，锅巴面板保存非法值会直接提示错误

**示例**

`alias: "huli"` 之后：

| 改造前 | 改造后 |
| --- | --- |
| `#群主查看 手机` | `#huli查看 手机` |
| `#群主在干嘛` | `#huli在干嘛` |
| `#群主用过什么` | `#huli用过什么` |
| `#群主更新` | `#群主更新`（固定不变，仍仅 Master 可用） |
| `#群主帮助` | `#群主帮助`（固定不变） |

帮助卡片底部会标注当前别名，改名后发一次 `#群主帮助` 即可确认新指令。

### 后台保活与 Shizuku（可选）

- 上报服务使用 `specialUse` 前台服务类型，避免 Android 15 对 `dataSync` 的每日约 6 小时配额；配合 START_STICKY、任务划掉自动重启与 15 分钟看门狗闹钟，降低"滑到后台就断连"的概率。
- 安装并运行 Shizuku（`https://shizuku.rikka.app/`）后，首页「Shizuku 增强」面板可一键完成：代为授予使用情况访问权限（拿到前台应用、24 小时使用时长与打开次数）、加入电池/Doze 白名单、把待机桶设为 active、放宽后台运行限制。未安装或未授权时全部能力自动降级，不影响上报。

### 蓝牙手表（可选）

首页「蓝牙手表」卡片可连接 HryFine 协议手表（市面上大量白牌手环/手表使用该协议），把表端数据合并进每次上报：

- 首页「扫描连接」进入独立的连接页：扫描附近 BLE 设备、手动选择自己的手表，页内显示握手进度，成功后自动保存设备，下次打开应用直接回连
- 连接后按 HryFine 流程完成随机数挑战、设备信息、`0x03` 绑定、校时与数据同步；绑定被拒绝或选错设备会自动清除记录并提示重新选择
- 同步内容：电量、今日步数/距离/卡路里、最近心率、血压、血氧、睡眠时长、久坐与抬腕开关、固件版本
- 距离由手表固件按步长模型估算（单位米），App 直接取用：当天总计走 `0x05/0x0C`（步/距/卡三个大端 u32，官方上限 240000 步、192000 米、4464000 千卡），24 小时逐时数据走 `0x05/0x02`（2 字节日期前缀 + 每小时 `步 u16、距离 u16、卡路里 u32`，大端；`0xFFFF` 视为该小时无数据，单小时超过 20000 步按字节序错位丢弃该小时），当天整包 `0x05/0x0A` 同样解析（含日期前缀的逐时整包或总计三元组）。大端为官方向序，小端与 u16 三元组仅作旧固件兜底，且逐时汇总优先于总计三元组，避免把桶数据按错误字节序读成假步数
- 卡路里字段的单位是「卡」而不是千卡：8685 步会回 `129240`，App 按每步量级自动换算成 `129 千卡`后再上报；直接给千卡的固件保持原值，插件端也做了同样的兜底换算
- 同步严格按官方握手顺序：先发 `0x05/0x06`（payload `0x01`）打开实时步数推送，**等手表 ACK `cmd=6` 之后**再发 `0x05/0x01` 请求全部历史（直接连发会被手表当重复请求丢掉，表现为时好时坏），收到手表自己的 `0x05/0x08` 结束包即提前收尾；1.5 秒内没等到 ACK 才兜底直接发 `0x05/0x01`
- 步数在连接期间每分钟刷新一次：`0x05/0x0C` 未回包时改用 `0x05/0x02` 的逐时汇总，因此不会停在首次连接时的数字；跨天后先清空昨日步数再拉新数据；定时刷新在完整同步期间自动让路，避免打断正在推送的历史流
- 睡眠 `0x05/0x09` 按官方布局解析：`[0..1]` 日期（压缩位域）、`[2..3]` 入睡、`[4..5]` 浅睡、`[6..7]` 深睡、`[8..9]` 起床、`[10..11]` 清醒，全部大端 16 位。睡眠只能由手表在历史流里主动推送，客户端点发 `0x09` 没有意义，因此不再单独请求；三段时长必须与入睡到起床的跨度自洽（不超过跨度、也不少于一半），错位读出的数字会被丢弃而不是当成睡眠上报；清醒字段异常时只丢清醒、保留睡眠时长；手表只回入睡/起床分钟时用两者差值当总睡眠（自动处理跨零点）；日期早于昨天的历史记录直接忽略
- 睡眠监测本身由手表按窗口统计（`0x02/0x0F` 五个字节：开关 + 入睡/起床分钟数，大端）。App 连上后读回该设置并写日志「手表睡眠监测 开关=… 窗口=…」，若发现开关被关掉就按原窗口重新打开——开关关着时手表根本不生成睡眠记录，客户端怎么请求都拿不到
- 手表在**每次连接建立后只推一次睡眠**，同一连接内再发 `0x05/0x01` 只会回步数等数据。因此手动同步（首页「立即同步」）时若睡眠缺失或超过 30 分钟没更新，本轮结束仍没拿到就自动断开重连一次（日志「本轮同步没有拿到睡眠，重连手表重新拉取」），效果等同重进 App；同步过程中还会补发 `0x05/0x03`（睡眠历史）尝试让手表重推，固件不支持时忽略。自动同步只在睡眠超过 6 小时没更新时重连，且重连冷却 1 小时，避免频繁占用蓝牙
- 血氧 `0x05/0x0E`（部分固件用 `0x05/0x1C` 回测量结果）取 `[11]` 的百分比，再兜底「条数 + 8 字节记录」与尾部单值两种布局，只接受 50~100% 的生理区间，`0xFF` 填充值不会被当成数据。心率和血压同样按官方的 40~160 次/分、收缩压 50~300、舒张压 30~200 过滤，越界样本直接跳过
- 每轮同步结束（`0x05/0x08`）后立刻补发一次上报，插件不必等下一轮定时上报就能看到新步数（日志记为「即时上报(手表数据同步完成)」）
- 手表默认不自动测量，卡片内「测心率 / 测血压 / 测血氧」可主动触发一次测量；结果回传后卡片自动刷新，并立刻补发一次上报（日志记为「即时上报(手表心率测量完成)」），不必等下一轮定时上报
- 设置页「手表自动同步」可开启定时同步：选择同步间隔（5~360 分钟），并按需打开「自动测量心率 / 血压 / 血氧」；开启后上报服务常驻期间会按间隔自动拉取手表数据（未连接时自动尝试回连），每次同步后依次触发已开启的测量项，测量完成即时上报。所有改动保存即生效，无需重启
- 只读取表端数据，不改动用户设置；仅在绑定成功后按官方 App 的方式打开配对开关，测量也只由你在卡片上手动触发
- 手表要求系统配对时自动发起蓝牙配对；连续快速断开会放慢重连节奏（最长 60 秒一次），避免反复占用蓝牙
- 卡片与连接页都提供「解除绑定」：通知手表解绑、取消系统配对并清除已保存设备
- 每次连接成功都会自动拉一次当天数据；点卡片上的手表名称可以改名，改名后上报、服务端与插件展示都使用新名称
- 运行日志页默认显示最近 24 小时，支持一键复制；日志页顶部说明与按钮分行显示
- 断线后按 5/10/20/40/60 秒指数退避自动重连，选错设备会自动清除记录并提示重新选择
- 手表不需要在表上确认绑定：读取设备信息成功后立即进入已连接，先发只读的数据请求，确认链路稳定后再补校时
- 若手表仍被官方 App 占用导致反复断开，请先在原 App 或手表「设置 → 解绑」中解除，再用本应用连接
- 手表数据以 `watch` 对象附在原有上报 payload 中，插件状态卡、详情卡与全部设备卡自动展示手表区块
- Android 12 及以上申请「附近的设备」权限，Android 11 及以下使用定位权限扫描 BLE；拒绝授权时仅手表功能不可用，不影响原有上报

## 分支说明

| 分支 | 内容 | 用途 |
| --- | --- | --- |
| `master` | 完整源码：Android App、Go 服务端、TRSS-Yunzai 插件、文档与构建脚本 | 日常开发与提交目标，Issue/PR 请提交到这里 |
| `main` | CI 从 `master` 的 `plugins/mugshot` 自动生成的孤儿快照，根目录即插件本体 | 供 Yunzai 直接 `git clone -b main` 安装，也是插件自更新的拉取源 |

`main` 是只读快照分支，每次推送到 `master` 时由 GitHub Actions 强制覆盖，直接修改会在下次同步时丢失。

## 快速开始

1. 部署 `mugshot-server`（Ubuntu ARM64 / x86_64，systemd 常驻）：`uname -m` 确认架构后，下载 Release 对应架构的 `.deb` 直接 `sudo apt install ./xxx.deb`，装完即自动运行；有桌面时应用菜单点"Mugshot 服务端"打开图形管理面板，纯 SSH/无桌面用 `sudo mugshot-ctl status|devices|show|token|config|set|logs|restart` 完成查看与设置，详见 `docs/DEPLOY.md`
2. 安装插件到 TRSS-Yunzai 的 `plugins/` 目录：`git clone -b main https://github.com/huliaiya/Mugshot.git mugshot`（`main` 分支根目录即插件本体，完整源码在 `master`），配置 `config/mugshot.yaml`（服务端地址与 Token，与 App 共用同一个）
3. 安装 Mugshot APK（Release 下载，已签名，包名 `com.Mugshot.huli`，可直接安装），同意隐私政策，授予使用情况访问权限，填写服务端地址与 Token，开启上报

详细部署与三端联调配置见 [docs/DEPLOY.md](docs/DEPLOY.md)。

## 构建

| 产物 | 方式 |
| --- | --- |
| Android APK | GitHub Actions `build-android.yml`，或本地 `cd android && ./gradlew assembleRelease` |
| mugshot-server Linux | GitHub Actions `build-linux`（ARM64 与 x86_64 矩阵构建），每种架构产出 `.deb`（`apt install` 即装）、`.tar.gz`、裸二进制与 GUI；本地 `cd server && CGO_ENABLED=0 go build` |
| 插件 | 纯源码，无构建步骤；Release 附带 `mugshot-plugin_<版本>.tar.gz`，插件内容同时自动同步到 `main` 分支（可直接 `git clone -b main` 安装） |

三端均内置更新检查（启动时与每日一次，GitHub Releases，主源失败自动尝试备用源）与手动更新入口。

## 安全与隐私

- Android 端仅采集前台应用名称、屏幕状态、电池、网络类型、各应用前台使用时长等状态字段，不上传输入内容、屏幕文本、剪贴板等敏感数据；权限用途逐条见 `docs/PRIVACY.md`
- 首次启动展示隐私政策，用户同意前不采集、不上报任何数据（见 `docs/PRIVACY.md`）
- App、插件与 GUI 共用同一个 Token 鉴权，服务端校验 device_id 与 token 绑定关系
- 服务端轮换 Token 后旧 Token 立即失效；GUI 与插件在收到 401 时会自动从本机服务端同步新 Token 并重试（远程服务端需手动填写）
- 服务端默认仅保留最近 7 天（可配置）数据；生产环境建议通过反向代理启用 TLS
