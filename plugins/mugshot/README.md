# Mugshot 插件（TRSS-Yunzai）

基于 TRSS-Yunzai 的设备状态远程查看插件。群成员在 QQ 群内发送指令，即可查看群主 Android 设备的当前使用状态：正在使用什么 App、屏幕是否亮着、电量、充电状态、网络类型、设备名称等。支持多台设备，每台设备在 App 内自定义名称，群内按设备名查询。

本仓库 `main` 分支根目录即插件本体（用于直接克隆安装）。服务端与安卓端的完整项目见 `master` 分支。

## 分支说明

| 分支 | 内容 | 说明 |
| --- | --- | --- |
| `master` | Android App、Go 服务端、插件与文档的完整源码 | 开发与提交目标，Issue/PR 请提交到这里 |
| `main` | 由 CI 从 `master` 的 `plugins/mugshot` 自动生成的快照 | 根目录即插件，供 `git clone -b main` 安装与插件自更新 |

`main` 为只读快照，每次推送到 `master` 都会强制覆盖；直接修改 `main` 的内容会在下次同步时丢失。

## 安装

把本插件克隆到 TRSS-Yunzai 的 `plugins/` 目录：

```bash
# 进入 Yunzai 根目录的 plugins
cd Yunzai-Bot/plugins

# 克隆插件（main 分支即插件本体）
git clone -b main https://github.com/huliaiya/Mugshot.git mugshot
```

依赖说明：

- 需要先部署并运行 `mugshot-server`，获取其访问地址与统一 Token
- WebSocket 订阅使用 Yunzai 根目录自带的 `ws` 依赖；Node 22+ 也可使用内置 WebSocket。缺失时插件自动降级为纯 HTTP 查询
- 插件无独立构建步骤，克隆后重启 Yunzai 即可加载
- 只有以 `git clone` 安装（目录内含 `.git`）才能使用 `#群主更新` 一键更新插件；用 tar 包解压安装的目录不是 git 仓库，更新时会提示改用 git 安装

## 配置

配置文件为 `config/mugshot.yaml`，插件启动时会自动生成。可手工编辑，也可在锅巴面板（Guoba）里可视化修改，两种方式共用同一份配置，改完即时生效，无需重启 Yunzai。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `alias` | `群主` | 指令前缀，改后查询指令变为 `#huli查看` 等；`#群主帮助`、`#群主更新` 固定不变 |
| `server_url` | `http://127.0.0.1:8080` | mugshot-server 地址（含端口） |
| `token` | 空 | 统一 Token，与手机 App 共用同一个；在服务端 GUI 的"设置"或"接入信息"页获取 |
| `plugin_token` | 空 | 兼容旧配置的令牌键名，`token` 为空时作为后备 |
| `detail_fresh` | `true` | `#群主详情` 是否默认触发一次实时上报 |
| `fresh_timeout_ms` | `8000` | 等待设备按需上报的超时（毫秒） |
| `fresh_cooldown_ms` | `10000` | 同一用户重复触发实时上报的最小间隔（毫秒），冷却期内自动展示缓存数据 |
| `device_btn_per_row` | `5` | 设备选择卡片每行放几个按钮（最多 10） |
| `github_repo` | `huliaiya/Mugshot` | 插件更新时若插件目录的 git 没有 origin，则回退到此仓库拉取 main 分支（格式 `owner/repo`） |
| `auto_update_check` | `true` | 启动时与每日 9 点检查更新（仅写日志提示，不自动更新） |

### 锅巴面板（Guoba）

若已安装锅巴面板（guoba-plugin-next），插件会在面板中注册"服务端连接""查询行为""更新"三组可视化字段，并提供"测试连接"按钮：用表单里填写的地址与 Token 请求一次服务端 `/health`，验证连通性。在面板里修改服务端地址或 Token 并保存后，插件会自动断开旧订阅并按新配置重连。

## 指令

| 指令 | 说明 | 权限 |
| --- | --- | --- |
| `#群主帮助` | 查看指令列表 | 所有人 |
| `#群主列表` | 渲染所有设备列表（在线状态、最后上报时间），附选择按钮 | 所有人 |
| `#群主查看 [设备名]` | 带设备名查询单台实时状态（fresh），设备离线或超时降级返回 cache 数据；不带设备名渲染全部设备快照 | 所有人 |
| `#群主在干嘛` | 渲染全部设备此刻的状态与信息（在线、正在使用的软件、电量、屏幕、网络等），并发触发一轮实时上报后渲染成图片 | 所有人 |
| `#群主详情 [设备名]` | 返回完整字段状态卡片 | 所有人 |
| `#群主状态` | 查看服务端健康状态与版本、可用更新 | 所有人 |
| `#群主更新` | 用宿主更新机制更新插件本体：自动拉取源码、按需安装依赖并按宿主逻辑重启（与 Mugshot 服务端无关） | Master |
| `#群主更新日志` | 查看插件最近提交记录 | 所有人 |

### 指令别名

默认前缀为 `群主`，可在锅巴面板「指令 → 指令别名」或 `config/mugshot.yaml` 的 `alias` 字段修改：

- 查询类指令跟随别名：`查看`、`详情`、`在干嘛`、`列表`、`用过什么`、`状态`、`更新日志`
- `#群主帮助` 与 `#群主更新` 固定不变，改名后仍能查看帮助、改错别名也能更新恢复
- 允许中文、字母、数字、下划线，长度 1-12；开头的 `#` 自动去掉；非法值回退 `群主`
- 面板保存即时生效，无需重启 Yunzai；手改 yaml 后需重启
- 改名后旧前缀立即失效，卡片提示与按钮文字会同步成新前缀

示例：`alias: "huli"` 后 `#群主查看 手机` → `#huli查看 手机`，`#群主在干嘛` → `#huli在干嘛`。

说明：

- `#群主在干嘛` 与 `#群主列表` 的设备卡片在 QQBot 适配器下附带设备按钮，点击即查看对应单台
- 所有回复均优先渲染为图片；QQBot 适配器下附带可点击按钮，其他协议端自动降级为纯图片
- 渲染走三级渲染链：`e.runtime.render` → 宿主 `lib/puppeteer/puppeteer.js`（huli-plugins 同款，绕开 runtime 依赖）→ `Bot.renderer`；宿主能渲染其他插件的图即可渲染本插件图
- 卡片风格为随机背景图（`https://t.alcy.cc/mp`，5 分钟自动更换，获取失败回退渐变底色）+ 半透明毛玻璃面板 + 彩色文字：每张卡片随机一组色板，标题渐变字、标签与数值按色板着色
- 出图为 PNG 并按 2 倍缩放渲染（zoom: 2），文字清晰无压缩噪点
- 实时上报有冷却（`fresh_cooldown_ms`），同一用户短时间内重复触发会自动展示缓存数据，避免频繁唤醒手机

## 更新

- 启动时与每日定时检查更新，仅记录日志；`#群主更新` 走宿主内置更新机制（TRSS/Miao 的 other/update.js）更新插件本体，自动处理依赖安装与重启，宿主机制不可用或更新失败时回退为直接拉取 main 分支源码；服务端更新由服务端自身的定时检查或 GUI"设置"页负责，插件不参与
- 更新与检查更新支持镜像加速：GitHub 直连失败（如 GnuTLS recv error）时自动依次尝试常见公共镜像（ghfast.top / gh-proxy.com）；也可在 `config/mugshot.yaml` 的 `github_mirror` 填自定义镜像前缀（如 `https://ghfast.top/`），配置的镜像优先
- 插件更新 = 拉取仓库 `main` 分支源码并覆盖本地插件目录（`git fetch` + `git reset --hard`），因此插件需以 `git clone -b main` 方式安装；插件版本以本地提交短哈希表示
- 远端地址优先取插件目录的 `origin`，缺失时回退到 `github_repo` 配置；服务端更新走服务端自更新链路（下载新版本替换二进制后自动重启）

## 安全与隐私

- 插件仅转发状态字段（前台应用名称、屏幕、电量、网络类型等），不上传输入内容、屏幕文本、剪贴板等敏感数据
- 插件、手机 App 与服务端 GUI 共用同一个 Token 鉴权
- 服务端轮换 Token 后旧 Token 立即失效；插件收到 401 时会自动从本机服务端同步新 Token 并重试一次（远程服务端需手动填写）
